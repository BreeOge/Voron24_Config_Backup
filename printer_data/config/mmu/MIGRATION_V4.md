# Happy Hare v3.42 -> v4.0 migration

This branch contains a **manual migration seed** for the Happy Hare v4 configuration layout. The original v3.42 configuration remains untouched on the repository's `main` branch.

Happy Hare v4 is a breaking rework. Upstream's supported v3 -> v4 path intentionally starts from a fresh v4 configuration rather than automatically translating v3 settings. These files translate the known working BreeOge hardware/tuning values into v4-native section names and semantics so the v4 builder can refresh them into complete current generated files.

## New v4 layout

- `base/mmu.cfg` - shared logical MMU, shared printer/toolhead settings, gantry cutter servo and Blobifier hardware.
- `base/mmu_hardware_unit0.cfg` - physical MMU for logical gates 0-3 (old `mmu_2`, BTT MMB v2.0 family).
- `base/mmu_hardware_unit1.cfg` - physical MMU for logical gates 4-7 (old `mmu`, BTT MMB v1.0 family) plus the shared proportional buffer ADC.
- `base/mmu_parameters_unit0.cfg` - migrated per-unit movement/homing/FlowGuard tuning for gates 0-3.
- `base/mmu_parameters_unit1.cfg` - migrated per-unit movement/homing/FlowGuard tuning for gates 4-7.
- `base/mmu_macro_vars.cfg` - migration seed containing the user's macro, cutter and Blobifier tuning. The v4 builder should refresh this into the complete current file.
- `macros/` - **owned/generated by Happy Hare v4**. Do not restore the old Blobifier file here; the installer installs the current upstream macros.
- `optional/client_macros.cfg` - **owned/generated by Happy Hare v4** when client macros are enabled.
- `user/breeoge_blobifier.cfg` - user-owned v4 extension preserving the old custom 14 mm Blobifier seal-parking modification without patching upstream Blobifier code.

## Physical unit mapping

Logical gate numbering is intentionally preserved:

| v4 unit | Old MCU | CAN UUID | Old logical gates | Board family |
|---|---|---|---:|---|
| `unit0` | `mmu_2` | `44d2de76b2ab` | 0-3 | BTT MMB v2.0 |
| `unit1` | `mmu` | `a99262006fa1` | 4-7 | BTT MMB v1.0 family / custom wiring |

The gate-6/local-gate-2 direction pin on `unit1` remains `PD3` because that is what the working v3 configuration used, even though current generic MMB v1 defaults differ.

## Important semantic translations

- v3 `gate_homing_endstop: mmu_gate` -> v4 `gate_homing_endstop: mmu_shared_exit`.
- v3 `gate_parking_distance: 23` -> v4 `gate_parking_distance: -23`. **Happy Hare v4 reversed this sign convention.**
- v3 `extruder_homing_buffer: 25` -> v4 `bowden_load_homing_buffer: 25`.
- v3 `gate_unload_buffer: 50` -> v4 `bowden_unload_homing_buffer: 50`.
- v3 pre-gate sensors -> v4 per-unit `mmu_entry_switch_pin_N` sensors.
- v3 shared `gate_switch_pin` list -> one `mmu_shared_exit_switch_pin` per unit.
- Toolhead sensors and geometry moved to shared `[mmu_toolhead default]`.
- Proportional sync feedback moved to `[mmu_buffer shared]`; both units reference the same buffer.
- Blobifier hardware moved from `addons/blobifier_hw.cfg` into v4 shared hardware in `mmu.cfg`.
- Blobifier variables moved into `[gcode_macro _BLOBIFIER_VARS]` in `mmu_macro_vars.cfg`.
- The old custom `variable_seal_offset: 14` patch no longer exists upstream. It is preserved using v4's `variable_user_post_purge_extension` hook and `user/breeoge_blobifier.cfg`.
- Old EREC servo-cutter addon was not actually active: its servo hardware was commented out and the post-unload extension was empty. It is therefore not enabled in v4. The active toolhead `_MMU_CUT_TIP` / gantry-servo cutter is preserved.
- Old eject-button addon was not included by `printer.cfg`; it is not enabled in v4. v4 now supports eject buttons natively if they are added later.

## Before first v4 restart

Happy Hare's v4 Klipper modules and upstream macro files still must be installed by Happy Hare itself. From the Happy-Hare checkout on the printer, run the interactive multi-unit installer:

```sh
cd ~/Happy-Hare
./install.sh -n -i
```

Use these selections as the basis for menuconfig:

1. Multi-unit setup with `unit0` and `unit1`, four gates each.
2. Both units are `Other` / `VirtualSelector` / multi-gear / always-gripped, with variable bowden and rotation distances.
3. `unit0`: CAN `44d2de76b2ab`, `can0`; BTT MMB v2.0-family pinout, but retain the explicit pins in this branch.
4. `unit1`: CAN `a99262006fa1`, `can0`; BTT MMB v1.0-family pinout, retaining the explicit/custom pins in this branch.
5. Shared toolhead sensors: extruder entry `SB2209:PB7`, toolhead `SB2209:PB5`.
6. Toolhead cutter enabled; gantry bumper servo on `PG12`.
7. Blobifier enabled, servo type: servo `PG9`, bucket switch `^PG13`, pulse widths `0.00053` / `0.0023`.
8. Proportional sync-feedback buffer enabled and shared by both units: analog pin `unit1:PA3`, range 6, max range 12, raw compression 1, raw tension 0, neutral 0.50. Spring state is left `none` because v3 did not define one.
9. No MMU encoder, eSpooler or MMU LED hardware was active in the v3 config.
10. Enable Happy Hare client macros.
11. Use the existing printer-wide save-variable file: `~/printer_data/config/config/save_variables.cfg`.

After menuconfig saves, let `install.sh` build/install the complete current v4 `base`, `macros`, and `optional` files. Review its diff before restarting Klipper.

## First-start checks

Before a real print, verify both units and sensors independently. At minimum: MCU connectivity, each local gear motor direction, all eight entry sensors, both shared-exit sensors, toolhead sensors, proportional buffer direction/value, gate homing/parking, cutter motion, Blobifier tray/brush/seal parking, and a dry tool change on gates from both units.

The `main` branch remains the untouched v3.42 reference if any value needs to be compared during commissioning.
